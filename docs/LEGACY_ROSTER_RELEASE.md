# 原檔名冊正式顯示

歷史封存與正式名冊是不同資料。這次將選定封存中的人名、機台／工作站欄位建立成正式資料列，保留來源位置，全部標為待確認。

- 舊員工、機台與產品停用保留，開放工單改為取消保留；不刪除歷史封存、帳號、日曆或稽核紀錄。
- 明確的「包裝-甲+乙」拆成人員候選，其他別名、註記或人力備註不推測合併。
- 不推測員工技能、工序、產能、件數、交期或開始時間。不新增正式工單或排班。
- 名冊待確認期間，前端不啟動瀏覽器備援／OR-Tools，求解 API 拒絕請求，資料庫拒絕預覽與排班寫入。
- 機台卡片顯示實際名稱與代號，兩廠分開顯示，點開可核對原表欄位。

## 維護匯入

先完成並驗證全資料庫備份。管理員在單一交易內套用 0018、讀入 `db/maintenance/import_legacy_roster.sql`，再呼叫 session-local `pg_temp.import_legacy_roster(archive_id, expected_version)`。此工具不是提供給使用者的 RPC。

匯入前核對所選來源、版本、舊名冊數量。若已有實際排班、版本變動或已匯入來源名冊，工具會拒絕，不可跳過保護。維護完成後重新載入正式站，核對兩廠人數、欄位數、原檔來源及待確認提示。
