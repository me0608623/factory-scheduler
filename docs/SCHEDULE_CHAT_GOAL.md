## 架構與資料邊界

- 目前優先使用結構化檢索，不先把整個資料庫送向量庫。不需要 RAG 向量索引才能查「這天誰有工作／故障／待料」。未來 SOP、歷史 Excel 與非結構文件問答才評估額外檢索。
- 本機不勾雲端 AI 時完全在瀏覽器做資料查詢，不需要排程服務，不冒充模型回答。
- 雲端資料查詢只呼叫自己的排程服務與 Supabase。依登入者 RLS 讀資料，開放 boss／lead，尚未開放 worker／viewer。可用證據不等於完整資料權限模型已完成。
- 免費文字備註、金鑰、email、來源註記、身份候選不納入模型依據；目前人員姓名、工作與工單代號、時間、預排件數及提問可能包含公司敏感資訊，因此真正 AI 預設關閉。
- 聊天室沒有 SQL 工具、寫入工具、任意 URL、排程套用功能，也不依聊天文字決定員工聘任、獎懲或其他高影響結果。
- 文字以 `textContent` 顯示；不直接渲染模型 HTML／Markdown。資料中的惡意指令不能變成寫入授權。
- 對話只存在分頁記憶體，最多六則用於模型上下文、最多三十個畫面訊息；清除及重新整理不保存歷史到雲端。AI 依據最多一百筆，截短明示不足。不能由「沒找到」推出系統全面正常。
- 每次最多兩項後端聊天計算，排程求解有獨立槽位。上線前仍需要每使用者／租戶速率與費用上限、模型品質評估、端到端權限實測。

## 尚未啟用的模型設定

沒有讀取現有秘密、沒有把正式資料送出、沒有新增費用。以下只是伺服器端的設定介面，**不可放在 VITE_* 或提交金鑰**：

- `OPENAI_API_KEY`：由管理員在安全的伺服器環境輸入。
- `SCHEDULE_CHAT_MODEL`：待選擇，程式不偷偷指定付費模型。
- `AI_SCHEDULE_DATA_APPROVED=true`：需先具體確認「提問、有限對話及選定日期／廠別的排程依據」可以傳給 OpenAI；只填 key 不會啟用。
- 本機快照 AI 另外要求 `SOLVER_API_KEY`；正式環境應停用快照端點，走登入的 `/chat/db`。

使用 [OpenAI Responses API 官方說明](https://developers.openai.com/api/docs/guides/migrate-to-responses) 與 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)；設定 `store:false`、無工具、有限輸出與 timeout，驗證完成狀態及引用代號存在。`store:false` 不等於完全無服務端留存；正式啟用前應核對 [官方資料控制](https://developers.openai.com/api/docs/guides/your-data)。引用存在也不證明回答內容正確，仍需真模型評估。
