# 開源排程借鏡與本輪優化（2026-09-29）

## 查閱來源與界線

- [frePPLe 資源報表](https://frepple.com/docs/current/user-interface/plan-analysis/resource-report.html)：呈現可用量、負荷與利用率。
- [frePPLe 功能說明](https://github.com/frePPLe/frepple/blob/master/doc/features.rst)：描述例外導向工作、資源池、技能、換模矩陣及跨地點供應鏈。
- [Timefold 開源 quickstarts](https://github.com/TimefoldAI/timefold-quickstarts)：員工排班的工作量平衡、包裝排程的固定工作，以及允許未指派工作的範例。
- [frePPLe 版本比較](https://frepple.com/editions/)：部分進階功能屬商業版本，不能把整份功能表都稱為免費開源現成功能。

只借鏡產品設計與分析概念，沒有複製第三方程式或增加依賴；保留目前 OR-Tools、Supabase 與前端架構。Timefold 雲端 Employee Shift Scheduling 的進階模型也不等於開源 quickstart。

## 與現有程式對照後的優先順序

| 方向 | 目前狀況 | 後續邊界 |
| --- | --- | --- |
| 人員／機台負荷與空檔 | 本輪完成當日唯讀總覽 | 先分析已排工作，不宣稱能預測整廠瓶頸 |
| 未排工作與原因集中清單 | 已有未排狀態、單一操作的原因提示；尚無完整統一工作清單 | 下一輪可合併缺技能、缺機台、未排量、逾期等，附直接操作入口 |
| 可保存的 what-if 情境 | 已有暫時方案對照；尚無命名、保存、版本化情境 | 必須隔離正式資料並防止過期情境覆蓋現況 |
| 開始／完成／實際件數回報 | 有排程歷史與固定工作，不等於現場回報流程 | 應設計多人回報、權限、重送冪等與計畫對實際差異 |
| 預防性保養／共用模具資源 | 可報故障，尚無完整保養與模具占用模型 | 須先確認設備、模具識別與作業規則，不能自行設定週期 |
| 工作量公平／減少重排擾動 | 有固定工作與方案變動對照，尚無可設定的公平性目標 | 先定義跨機台工作的負擔算法與公平週期 |
| 換模、多人同機與跨廠交接 | 尚未有經核定的完整規則 | 不把人力分組名稱當作產能或最少組員數 |

## 本輪完成：當日負荷

- 頂部新增「當日負荷」；依選取日期及 1 廠／2 廠／跨廠查看，所有可讀排程的角色皆可查看。
- 機台及員工分開排序；顯示可用分鐘、已排段數、占用分鐘、利用率、總空檔與最長空檔。分析的是目前畫面資料，是否已存到雲端須看同步狀態。
- 可用時間依既有上班日、午休、當日加班、個人加班與請假規則；機台故障時段（含已修復的歷史區間）扣除，和現行排程器一致。
- 一人同時顧多台，實際占用取時間聯集；各機台工作的分鐘合計另外顯示，不把兩台並行一小時寫成工作兩小時。
- 機台重疊、超過員工顧機上限、不在可用時段及格式／關聯缺漏分別警示，不被最高 100% 的利用率掩蓋。
- 待確認名冊不計可用產能、利用率、空檔或顧機上限；可顯示原始已排時間，但不推定正式規則。
- 忽略名冊分組篩選，避免多組員工重複計算或隱藏其他員工。方案預覽期間停用此入口，以免把試算誤標為已儲存排程。
- 空檔只表示時間未占用；不保證符合技能、物料、前後工序與交期。高利用率不自動等於真正生產瓶頸。
- 不修改排程、不寫 Supabase、不新增 migration、不更換求解器、不部署 Render。
