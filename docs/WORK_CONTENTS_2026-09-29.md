# 工作內容、設備／工位與排班

## 本輪範圍

開發分支 `codex/work-content-resources-20260929`。本轮只修改本機程式並測試，不推送或合併 main、不套用正式 Supabase migration、不部署 Render。原始 Excel 未修改，也不納入 Git。

系統現在分開保存三部分：

| 部分 | 資料 | 介面與用途 |
| --- | --- | --- |
| 工作內容 | `workContents` / `work_contents` | 名稱、廠別、是否需要設備、明確核定的人員與設備。既有產品工序仍保留原有產能模型。 |
| 設備／工位 | 既有 `machines` | 實體資源与待確認來源位置。不同工作可選同一設備，仍檢查占用與員工操作技能。 |
| 排班 | 既有生產 `blocks` 加獨立 `workAssignments` / `work_assignments` | 記錄人員、工作內容、可空白的設備、日期與起訖時間。純人工不新增假機台、不要求工序速率。 |

## 排班操作

1. 老闆到「工作內容」新增內容，明確選擇純人工或需要設備，勾選核定人員與允許設備。
2. 老闆／組長按「＋一般工作排班」，選工作、人員、日期與時段。設備型另需選設備且具操作技能。件數可留空，0 與未填分開。
3. 先預覽，確認後才存入。方塊可拖曳時段、移到同工作其他人員／設備欄，或拉底邊調整工作時間，以 10 分鐘為格點。
4. 新增、移動與拉伸都重新檢查人員、設備、請假、午休、上班日、加班意願與故障。取消不更動正式班表。移除未開始的一般工作也先確認，可復原。
5. 可選設備／工位或依工作內容排列。週檢視下的一般工作區明確顯示目前選定的那一天，不聲稱是全週圖。產品工序方塊拖曳在原設備檢視操作。

純人工保守採專心執行：即使員工可顧兩台，也不能在人工時段顧設備或做第二件人工工作。設備工作耗用一個顧機容量；設備本身仍獨占。若未來要支援低注意力人工工作，必須另定注意力權重，不能從 Excel 推測。

## 排程器與資料保護

- OR-Tools 與瀏覽器備援把一般工作當作固定占用，避開員工與設備。不自動指派／重排一般工作，也不把參考件數算成工單完成量。
- 故障或請假影響固定一般工作時，標明無法套用，要求手動調整，不偷偷清掉或搬移一般工作。
- 健康檢查新增 `work_assignments_v1` 能力。舊服務無此能力且已有一般工作時，前端改用已支援占用的瀏覽器備援，防止舊服務忽略資料。
- 加法 migration 0022：兩張新表、RLS、稽核、版本鎖、角色限定 RPC、跨表時間占用檢查、即時推送。工作定義只有老闆可改；老闆／組長可排班；其他成員只讀。
- SQL 與客戶端都拒絕會留下孤兒參照的名冊修改；工作定義不符合既有排班時整次撤回。失敗或版本衝突不留半份新排班。
- 儲存一般工作採完整版本提交，但 SQL 保留未變動列。未變動的過往工作不因日後變更每週行事曆而重寫；新增或修改列仍按規則驗證。
- 關聯工單結案後只保留唯讀參考代號，不讓它重新成為生產排程需求。
- 快照、情境、當日負荷、Excel 明細與 CSV 都包含一般工作。純人工不出現在設備格子，但在明細完整列出。範本尚未包含這兩張新表，已有一般工作時會阻擋整批覆蓋。

## 限制與正式上線前須知

這是一版可手動安排的獨立工作，不是將所有 1023 歷史文字自動轉成已核定工序。正式名冊仍保留 setup_pending 保護。

現場「開始／完成／實際件數」目前只支援原生產方塊；一般工作尚未接實際執行回報。參考件數與關聯工單只是備註，不能當成工單已做量。跨廠人員派遣、共用左右產能、夜班與搬運時間不在此版推定。

正式前需要人工驗收、備份與經同意的資料庫／服務／前端同步升級。0021 與 0022 尚未套用正式 Supabase。本分支沒有部署。
